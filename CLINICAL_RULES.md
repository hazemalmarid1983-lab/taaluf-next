# Clinical Rules

- Hide "Add Student" buttons and registration forms in /dashboard/parent if child is already registered.
- Restrict parent interface strictly to: Progress tracking, session reports, and teacher messaging.
- Goal mastery follows `DEFAULT_SKILL_TYPE_CONFIGS` in `lib/skillMastery.ts`; the nine developmental domains route to a skill type via `SKILL_CATEGORY_BY_DEVELOPMENTAL_DOMAIN`. Closed cognitive/language/motor: 100% × 3 consecutive sessions with an independent cold probe. Social: 80% × 4 sessions ≥24h apart, cold probe, ≥2 trainers. Self-help (ADL): 90% × 3 sessions ≥24h apart, cold probe, ≥2 settings, natural cue counts as independent. Self-regulation: frequency/duration criterion met in 5 sessions ≥24h apart with ≥2 trainers. Activity-level unlocks inside digital media keep 100% independence over 3 consecutive sessions.
- Generalization index (`lib/generalizationIndex.ts`): a probe succeeds at ≥80% independence and only counts outside training conditions (not the primary specialist, not the clinic, novel material). Each dimension scores distinct successes out of 3 (persons, places, novel-material successes); index = 0.34 person + 0.33 place + 0.33 material; ≥85 fully generalized, ≥50 partial.
- Goal mastery is sticky: once achieved it is dated (`mastered_at`) and only withdrawn by maintenance probes. Spaced maintenance (`lib/maintenanceSchedule.ts`): probes at 1, 2, 4 and 8 weeks after mastery, then a review every 12 weeks. A probe passes at ≥80%; a failed probe requires a confirmation probe within 48h; two consecutive failed probes withdraw mastery automatically (logged in `masteryWithdrawals`), the goal returns to re-acquisition, and only sessions after the withdrawal count toward re-mastery.
- Prompt levels use one 8-level scale (`ClinicalPromptLevel` in `types/clinical.ts`): Independent, Partial Verbal, Verbal, Gestural, Model, Partial Physical, Full Physical, No Response — same order as `PROMPT_HIERARCHY_ORDER`. A session records its most intrusive prompt; "Independent" is only valid at 100% independence.
- Digital prompt mapping (`DIGITAL_PROMPT_MAPPING` in `types/clinical.ts`, status `pending_scientific_signoff` until the clinical consultant signs off). Digital games record the on-screen cue per trial; it maps to the 8-level scale as follows:

  | Digital cue (`TrainingPromptLevel`) | On screen | Clinical level |
  | --- | --- | --- |
  | `visual_hint` | Target area highlighted, all choices remain | Gestural |
  | `reduced_choices` | Least-similar distractor removed | Gestural |
  | `direct_visual_assistance` | Target with one distractor, target highlighted and guided (demonstration) | Model |

  Rules: (1) each trial is mapped on its own; (2) any digital cue makes the trial non-independent, and no digital cue maps to Independent or above Model; (3) the session level is the most intrusive level across trials, and when only a digital cue reached it the goal session records `promptSource: 'digital_assistance'` and `digitalPromptCue` (ties pick the higher-ranked cue), otherwise `promptSource: 'human'`; (4) the server re-derives `promptLevel` from `digitalPromptCue` and the session form rejects a level that contradicts the mapping (`DIGITAL_PROMPT_MAPPING_CONFLICT`); (5) response latency alone never sets the level. The session form, generalization probe form, game completion screens (collapsed observer section), training session detail/history and goal cards label the mapping (e.g. "Visual hint (digital) → Gestural").
- Functional Behaviour Assessment (`lib/fba.ts`, types in `types/clinical.ts`). ABC incidents (antecedent → behaviour → consequence, optional behaviour note and duration, whether the replacement behaviour was used) are recorded only inside frequency/duration sessions of self-regulation/behaviour goals, so each incident is one of the behaviour occurrences already counted: incidents may not exceed `behaviorCount`, and summed incident durations may not exceed `behaviorDurationMinutes` (`ABC_EXCEEDS_BEHAVIOR_COUNT` / `ABC_EXCEEDS_DURATION`); the server applies the same rule when sanitizing synced sessions. Sessions may also record `replacementBehaviorCount`. Each behaviour goal has one `fbaPlan` (operational definition of the target behaviour, required replacement behaviour, optional hypothesized function: escape, attention, tangible, automatic) edited by staff only (`update_iep_goals`) through the `fba_plan` goal action; non-frequency goals are rejected (`NOT_BEHAVIOR_GOAL`). The suggested function is descriptive (consequence weight 2, antecedent weight 1) and appears only with ≥5 incidents and a ≥50% dominant share; it is not an experimental functional analysis and never overwrites the specialist's hypothesis. Plan changes are audited (`fba_plan_updated`); session audits include the ABC count.
- Interobserver agreement (`lib/ioa.ts`, `POST/GET /api/children/[childId]/ioa`, draft pending scientific sign-off). A second staff observer (`record_session_trials`; never parents or the read-only advisor) records parallel data for a stored session. Primary data always comes from the stored session and is not shown to the second observer. The method follows what the session stored: total count (`behaviorCount`), total duration (`behaviorDurationMinutes`), or trial-by-trial (`trialScores`, the per-trial prompt levels optionally recorded in the session form or derived from digital games). Total count/duration IOA = smaller ÷ larger × 100 (0 vs 0 = 100%). Trial-by-trial IOA = trials with the same prompt level ÷ trials × 100, plus a separate independent/not-independent agreement. The second observer must differ from the session trainer (`SAME_OBSERVER`), must score the same number of trials (`TRIAL_COUNT_MISMATCH`), and may record once per session (`IOA_EXISTS`). A record meets the standard at ≥80%; the coverage target is IOA on ≥20% of comparable sessions. Supervisors (`manage_all_cases`, `manage_assigned_cases`, `review_clinical_content`) review mean agreement, coverage and records below 80% on the goals page. IOA records are audited (`ioa_recorded`) and removed with their goal.
- When a session records `trialScores`, independence % and the highest prompt level are derived from them, and entered values must match (`TRIAL_SCORES_MISMATCH`); the first-trial cold probe is taken from trial 1.
- EducationalIllustration components must match ABA targets across all domains.
- Free screening (`lib/screeningEngine.ts`) recommends a full assessment on any red-flag item (S8 response to name ≥2, S12 joint attention ≥2, S4 eye contact ≥2, S1 or S2 at 3), any dimension ≥67%, or an elevated overall score. Screening results must show the "not a diagnosis" notice and must not auto-redirect to pricing.
- Parent routes are enforced in middleware (`lib/parentRouteGuard.ts`): child-specific pages require a registered child; community pages are closed once a child is registered. The parent stage comes from the server record (`parentStageForUser`) and is carried in the signed session JWT (`token.parentStage`), refreshed on sign-in and `session.update()`; no client-set cookie is trusted.
- The server clinical record (`lib/server/clinicalRecordStore.ts`, one document per child) is the source of truth for goals, sessions, maintenance probes, generalization probes and assessment summaries. The browser copy is a cache synced by `lib/clinicalRecordClient.ts`. Sessions and probes are rebuilt on the server from form input (`lib/clinicalGoalActions.ts`), never accepted as computed goals.
- Child access: admin all children; scientific advisor read-only; specialist only when assigned (`POST /api/children/[childId]/assign`, admin); parent only their linked children. Parents may record sessions and generalization probes (always labelled `parent_report`) but not maintenance probes, status changes or goal deletion. Browser history is migrated once; later parent-added goals start without history. Deleted goals are never re-imported.
- Every clinical state change is appended to the per-child audit trail (`lib/clinicalAudit.ts`, `lib/server/clinicalAuditStore.ts`): goal created/deleted, status transitions, sessions, mastery achieved, phase changes, maintenance probe outcomes, mastery withdrawal, generalization probes, assessments, linking and specialist assignment. Staff read it via `GET /api/clinical-audit`.
- API routes check role permissions explicitly (`requireApiPermission`); unknown/guest roles get a session without `user` and a 403 from clinical routes.
